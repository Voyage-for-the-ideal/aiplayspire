## 目标与现状

- **现状**：对局结束（死亡/胜利界面）时 `/state` 报 `screen_type: "GAME_OVER"` 但没有任何可执行选项；手动退回主菜单后 `/state` 返回 `{"error": ...}`，Python 框架重试 10 次后退出。协议层完全没有"开局/选角色/设难度"能力：action 队列只在 `CardCrawlGame.isInARun()` 时被消费（`CommunicationMod.java:43-46`），`ActionController.executeCommand` 顶部还有一刀切守卫（`ActionController.java:34-37`）。
- **目标**：对局结束 → 自动回主菜单 → 自动选角色/设难度开局 → Neow 祝福由现有 LLM 链路决定 → 无限循环。默认配置：**铁甲战士 / A15 / 自动重开开启**，均可通过 `.env` 与命令行参数覆盖。

## 协议扩展（两侧接口契约）

`/state` 新增出对局状态（不再返回 error）：
- 主菜单：`{"screen_type": "MAIN_MENU", "choice_list": ["play"]}`（不含 player/floor 等对局字段）
- 角色选择：`{"screen_type": "CHAR_SELECT", "choice_list": ["IRONCLAD","SILENT","DEFECT","WATCHER"], "selected_character": ..., "ascension_level": ..., "ascension_max": ...}`
- GAME_OVER 保持现有完整状态，新增 `"game_over_reason": "defeat|victory|unlock"`
- 对局中状态新增 `character` 与 `ascension_level` 字段（用于日志与数据集）

`/action` 新增/复用：
- 复用 `choose`(choice_index)：GAME_OVER→点"返回主菜单"；MAIN_MENU→点 PLAY；CHAR_SELECT→选角色；NEOW→选祝福
- 复用 `proceed`：CHAR_SELECT 上点"开始游戏"
- 新增 `{"type": "set_ascension", "level": N}`：设置难度
- `NEOW_UNLOCK` 从 GAME_OVER 中拆出为新 `ChoiceType.NEOW`（否则开局 Neow 会被误判为"对局结束"造成循环误触发）
