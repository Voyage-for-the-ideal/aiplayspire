# 修改计划：PLAN 视野 8→1 + 新增 [HISTORY×8] 当前幕走过的路径 token

目标：消除 hindsight plan 的 padding 长度泄漏（近程桶 AUC 0.999 的成因），补上无泄漏、训练/推理同构的当前幕历史路径信号。按用户要求：**不含对现有 checkpoint 的量化评测**；**history 不做跨幕拼接**。

## 设计决策

1. **`PLAN_HORIZON = 1`**：人总会走进他死亡的房间，realized 下一间房几乎总存在 → "数 plan 长度读死亡"通道消失；训练（实际走的下一步）与推理（router 路线的下一步）语义差最小。`PLAN_TOKEN_DROPOUT=0.5` 保留。
2. **新增 `[HISTORY×8]`（仅当前幕）**：当前楼层之前本幕实际走过的房间符号（`symbols[:row]` 取末 8，左补 0），复用 `ROOM_SYMBOL_TO_ID`；带 history 距离 embedding（1..8，pad=`HISTORY_HORIZON`）；token type id=7（0-6 含义不变，item 仍为 6）。无未来信息、无 dropout；课程期与 map/plan 一起 mask。
3. **框架 plan 新鲜度修复**：`_last_plan_symbols` 现在是"MAP 决策时缓存、之后永不更新"的过期数据——D=1 时唯一的 token 会变成"当前所在房间"。改为存 `(锚定楼层, 路线符号)`，payload 构造时按楼层差移位取下一间，耗尽则省略（selectcard 自动 mask）。
4. **Token 预算**：`MAX_ITEM_TOKENS = 192 - 4 - 1 - 105 - 1 - 8 = 73`。
5. **版本硬拒载**：`MAP_CONTEXT_VERSION` → `"map-context-v2"`；`PREPROCESSING_VERSION` bump（dataset 拒绝旧 parquet）；`CHECKPOINT_FORMAT_VERSION` 7→8 并新增 `context_schema`（plan_horizon/history_horizon，加载时校验）。旧 v3 checkpoint/数据集显式失效。
