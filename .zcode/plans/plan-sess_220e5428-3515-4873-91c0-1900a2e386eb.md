# 事件全面本地化：per-choice 期望值打分（方案 A）

## 目标

`semantics_status == "KNOWN"` 的事件全部由本地价值网络决策（随机效果用枚举+期望，不再依赖 LLM）；
UNKNOWN 事件走已有文本解析兜底；事件中永远不再调用 LLM。战斗选项（`start_combat`）本期用保守规则处理，
战斗评估器（:5125）留待 v3 MAP expectimax 阶段统一建设。

改动范围：仅 `sts_ai_framework/`（+ 两处文档）。Java 侧 `EventStateExtractor` 已输出全部所需语义
（多 outcome 概率、`random_relic` pool、`select_cards` purpose/count），**无需 mod 改动与版本 bump**。

## 现状依据（已完成调研）

- LLM fall-through 三条路径：① COMPLEX 只有极保守 safe rule（`decision_mixin.py:508`），基本返回 None；
  ② DETERMINISTIC 循环里任一选项效果不支持就整体 `return None`（`decision_mixin.py:587-588`）；
  ③ stochastic 选项经 `_event_choice_effects`（`decision_mixin.py:352`）返回空 effects，被当 no-op 打分。
- 价值引擎 `selectcard/src/inference.py` `STSInferenceEngine`：`composite_event` 支持约 19 种效果类型
  （不支持的**静默忽略**）；`rank_cards_for_purpose(purge/transform/upgrade/duplicate)` 可用；
  **无批量前向 API**（逐条 evaluate，遗物池几十条逐个前向延迟可接受）；V 输入不含 potions。
- 无 Python 侧 :5125 客户端（战斗评估本期不做的原因）。
- CursedTome LAST_PAGE（`decision_mixin.py:734-741`）已是"枚举 realization 取 V 平均"的完整先例。

## 实施步骤

### 1. 基线埋点（先做，便于验收）

在 `_get_structured_event_decision` 各返回 None 的路径与 action_mixin 的 LLM 入口处，
按 `event.id/phase/decision_kind/原因` 打一行结构化日志。跑几局得到 fall-through 基线，改造后对比归零。

### 2. 池数据模块（新文件 `sts_ai_framework/event_pools.py`）

- 三幕 relic 池（common/uncommon/rare），以 `cardcrawl/` 反编译源码（`AbstractRelic` 各池）为准核对；
  `relic_pool(pool_name, act, owned_ids)`：处理 `ANY`/`RARE`/`BOOK`/`FACE`，剔除已拥有与不可再现遗物。
- `potion_pool()` 备用（注：V 输入不含 potions，`random_potion` 对打分近似无状态变化，只算同选项的确定性代价）。
- 纯数据+查表函数，无依赖。

### 3. per-choice 打分器（新文件 `sts_ai_framework/llm_agent_parts/event_expectimax.py`）

纯函数式，输入 `(GameState, value_engine)`，不依赖 mixin 状态：

- `classify_choice(choice) -> "SIMULABLE" | "COMBAT" | "UNSCORABLE"`：按 outcomes 的效果类型集合判定。
  `start_combat` → COMBAT；`mini_game`/`reveal_match_card`/`spin_wheel` 等已有特例的除外。
- `score_choice(state, choice) -> Optional[float]`：
  - **多 outcome**：`Σ pᵢ·V(S′ᵢ)`（expectimax，p 缺失按 1）。
  - **确定性效果**：`_apply_choice` + `evaluate_state`（现状路径）。
  - **`select_cards(purpose, count)`**：用 `rank_cards_for_purpose` 的最优目标直接落地 S′
    （purge→remove、transform→remove 近似、upgrade、duplicate），并产出与
    `_store_grid_intent_from_choice` 兼容的 intent 键（沿用 Bonfire `_rank_bonfire_targets` 模式）。
  - **`random_relic(pool)`**：枚举 `event_pools.relic_pool`，逐 relic 构造 S′ 取平均（CursedTome 先例泛化）。
  - **`random_upgrade(n)`**：枚举可升级卡（或 rank 前 k）取平均。
  - **`random_transform` / `choose_generated_card` / `colorless_card_reward`**：第一版近似——
    transform 按 remove_card 计；generated/colorless 奖励按 0 收益、只计确定性代价，局限写进注释，
    后续可加无色卡池。
- `decide_event(state, value_engine) -> Optional[GameAction]` 决策链：
  1. 剔除保证致死选项（沿用 `_choice_guaranteed_hp_loss` ≥ current_hp 规则）；
  2. 全部 enabled 选项可打分 → expectimax argmax；
  3. 部分可打分 → 可打分 argmax 与 LEAVE/no-op 基线比较（argmax 不优则选 leave）；
  4. 无可打分但有唯一 enabled 战斗选项 → 直接 CHOOSE（如 Colosseum INTRO）；
  5. 兜底 → 现有 `_get_safe_complex_event_rule`。

### 4. 接线与修 bug（`decision_mixin.py` / `config.py` / `action_mixin.py`）

- `_get_structured_event_decision` 重构为调用 `decide_event`（保留 GremlinMatchGame/CursedTome 特例与
  FORCED 快路径）；顺带修两个 bug：DETERMINISTIC 遇不支持效果改踢出候选而非整体放弃；移除 stochastic
  空效果当 no-op 的误判路径。
- `config.py` 新增 `EVENT_DECISION_POLICY = "expectimax" | "legacy"`（仿 `ROUTE_POLICY` 模式），
  legacy 走原逻辑，便于回滚与 A/B。
- `action_mixin.py`：KNOWN 事件在 expectimax 策略下不再落 LLM（决策链必返回动作）；
  UNKNOWN 事件改走已有 `_get_model_event_decision`（文本正则+价值网络）→ 安全默认，同样不进 LLM。
  LLM 代码保留（其他屏幕仍可用）。

### 5. 测试（`sts_ai_framework/tests/test_structured_events.py` 扩展）

复用现有 `make_state`/`choice`/`event`/`Harness`/Fake 引擎模式，新增用例：
stochastic 期望打分（如 DeadAdventurer：高概率正收益分支胜出）、`random_relic` 枚举平均与 owned 剔除、
`select_cards` intent 落地、战斗选项排除与唯一战斗选项直选、leave 基线比较、FORCED、UNKNOWN 走旧解析、
致死选项剔除。真实引擎测试沿用现有 skipTest-torch 模式。

## 风险与对策

- 遗物池数据错误 → 以 `cardcrawl/` 源码为准 + 单测抽查代表性遗物；池枚举只影响相对打分，近似权重不改变 argmax 方向。
- 局部模拟与真实效果的偏差 → 沿用仓库重放校验传统（自对弈 S′ 与真实 /state 比对）不在本期范围内，但日志会记录每个事件所选效果集，便于事后核对。
- 回滚：`EVENT_DECISION_POLICY=legacy` 一键恢复现状。
