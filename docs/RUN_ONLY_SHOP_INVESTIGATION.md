# 仅凭 `.run` 重建商店：调查结果（2026-10-25）

## 结论

普通选牌等其他决策的恢复能力已在检查现有 `RunReconstructor` 后重新评估，见 [更新后的可重建范围表](RUN_RECOVERY_CAPABILITIES.md)。现有重放器已经维护多项后续选牌状态；本报告的商店库存限制不表示后续牌组状态无法重放。

**一般情况下不能保证唯一恢复完整库存；在游戏版本、解锁状态和此前随机调用可确定的范围内，可以推导商店的部分内容。** 本次实际实现并运行了 `.run` 前缀探针，不再把完整快照复现当作历史恢复结果。

当前工具是研究探针，不是训练数据导入器。它没有证明任何本机历史商店的完整库存及价格均精确恢复，所有输出均为 `training_eligible: false`。

## 输入与边界

- 预测输入为 `.run` 中的种子、版本、角色、进阶、涅奥选择和商店之前的路径／选牌／事件／药水等记录。
- 游戏规则、内容目录及解锁包来自仓库只读原版源码和已验证游戏 jar；没有读取目标商店快照、存档或 RNG 状态。
- 当前购买、当前选择和后续记录不进入求解器；独立校验函数只能用购买记录否定候选，不选择随机状态或补齐库存。
- 不读取终局牌组、终局遗物列表或通关结果。测试明确修改这些字段及当前／未来记录，预测保持一致。
- 卡牌探针枚举自身角色的 0–5 级解锁状态，保留所有与前缀一致的分支。账号遗物部分只构造两个不同解锁假设用于寻找反例，没有穷举所有账号状态。
- 目前仅支持部分第一幕首商店前缀：普通战斗、部分事件和部分涅奥奖励；此前的精英、宝箱、其他商店、遗物副作用等暂未完整实现。每个商店共享 30 秒／10,000 次随机及循环工作步骤预算，比计划中的候选状态数上限更保守。

实际游戏 jar SHA-256：`cfad868ac8d65a88e71a0bf096fb09f78811e553effe0787c5309a655e081673`。原版内容解析还需要已有 JDK 的 `javap`，未安装新依赖，未修改或部署 mod。

## 本机实验结果

范围为本机 **38 份 `.run`、67 次商店访问**，不是完整训练归档的覆盖率。

| 探针结果 | 商店数 | 含义 |
|---|---:|---|
| 产生条件化的部分库存候选 | 7 | 在所建模前缀和解锁假设下预测 7 张卡、3 瓶药水及价格；仍缺完整遗物和状态证明 |
| 前缀与当前假设不一致 | 5 | 先前选牌或药水掉落记录与模拟不符，不能继续当作精确恢复 |
| 当前范围尚未解决 | 55 | 43 次含此前商店／精英／宝箱／换幕，3 次有遗物影响，9 次涅奥机制未覆盖 |

7 份部分库存候选中，**3 份又被当层购买记录否定**：缺少实际购买的物品。剩余 4 份中，3 份有卡牌购买记录可核对，1 份没有购买记录。它们都没有完整历史库存真值，因此不能称为“4 次重建成功”，也不能把 7/67 当作恢复率。

这些失败的原因尚未全部定位；不能擅自归因为读档、mod 或日志错误。也没有据此调整随机流计数使购买物品匹配。

另有一个独立结果：67 次访问都能在当前无信使补货假设下，从种子和此前商店次数推导 `merchantRng` 的特价槽位、价格浮动系数和请求遗物稀有度。原版初始商店消耗固定 16 次该随机流调用。**这只确定生成参数，不等于确定商品 ID 或完整售价**；售价还依赖稀有度、折扣、遗物池过滤等状态。此前持有信使的情况会被该组件拒绝。

## 普通初始商店也存在歧义：实际前缀反例

对局 `1786544667.run`：铁甲战士、A1、种子 `1215860580655121942`，第 3 层首商店。此前记录是涅奥升级、第 1 层选择 Clash（另两张为 Pummel 和 Reckless Charge），第 2 层拒绝 Liars Game。

只改变未在 `.run` 中记录的其他角色解锁状态，保留铁甲战士解锁等级为 5，就得到两套都通过探针所核对前缀约束的遗物库存：

| 槽位／价格 | 假设 A：其他角色解锁等级为 0 | 假设 B：四角色解锁等级均为 5 |
|---|---|---|
| 遗物 1／254 金币 | White Beast Statue（白兽雕像） | Self Forming Clay（自成型黏土） |
| 遗物 2／238 金币 | Mercury Hourglass（水银沙漏） | Toxic Egg 2（毒素之卵） |
| 商店遗物／153 金币 | Lee's Waffle（李家华夫饼） | Lee's Waffle（李家华夫饼） |

原因是其他角色解锁也会向共享遗物池加入内容，改变洗牌结果。`.run` 没有记录账号解锁档案；此前选牌不会约束这些其他角色的遗物解锁。该层没有购买记录提供额外观测。

这证明当前历史前缀不足以唯一确定该库存。它不声称两套库存中的某套就是当时实际库存，也没有利用终局记录挑选其中一套。

## 其他不可忽略的缺口

1. **卡牌随机流进度及稀有度修正。** 可以由已建模奖励逐步传播，但事件生成、额外奖励、特殊遗物和读档／mod 行为都必须明确处理。前缀匹配后仍有购买校验失败，表明当前模型还不完整。
2. **药水随机流。** 可以模拟战斗掉落判定、未领取药水的生成和实验室事件；仅看“获得几瓶药水”不足以计算调用数。炼制药水、熵之酿等还会生成额外药水，而日志不是完整操作轨迹。
3. **信使彩色牌补货。** 原版 `ShopScreen.purchaseCard` 调用 `getCardFromPool(..., false)`，最终使用独立的 `MathUtils.random`。界面闲聊、音效等也消耗这条流，其状态与调用时序未保存在 `.run` 中。即使账号全部解锁且初始库存可恢复，补货仍不能保证唯一恢复。
4. **库存与完整决策状态不同。** 恢复若干商品不代表恢复了当前药水槽、遗物计数、交易交错顺序、升级状态和全部合法动作。

## 验证与复现

新增工具：`selectcard/policy/shop_run_probe.py`。输出保留所有一致的自身卡牌解锁分支、两套账号遗物假设、前缀校验和独立购买校验，不生成训练样本。

从仓库根目录运行，输出路径必须是新的：

```powershell
conda run --no-capture-output -n spire python -m selectcard.policy.shop_run_probe --input-dir 'D:/Program Files/Slay the Spire/runs' --game-jar 'D:/Program Files/Slay the Spire/desktop-1.0.jar' --output debug/policy-reconstruction/run-only-20261025.json
```

本次报告产物为上述 `run-only-20261025.json`；中间 v1–v4 报告保留供审计，存在尚未修正的目录解析等问题，不作为最终结果。

```powershell
$env:STS_GAME_JAR = 'D:/Program Files/Slay the Spire/desktop-1.0.jar'
conda run --no-capture-output -n spire python -m unittest selectcard.policy.test_shop_run_probe -v
```

7 项检查通过，包括未来信息隔离、购买标签只做校验、解锁歧义反例、信使拒绝、共享预算，以及静态内容／遗物洗牌的引擎对照。最后一项在本机对 200 份已有引擎案例验证：仅由案例设计中的种子／角色／解锁等级生成的四类有序遗物池、卡池集合、药水目录和特价槽位均与引擎输出一致。引擎池／库存只作为对照标签，未传给预测器；这验证组件实现，仍不是 200 次 `.run` 历史恢复成功。

## 后续路线

优先明确历史数据的游戏／mod 版本和解锁档案；若数据提供方能保证当时全部解锁，可去掉一大类歧义。之后扩展前缀状态传播，定位当前不一致与购买校验失败，并增加仅给 `.run` 输入、完整库存作独立真值的盲测。只有所有保留分支的完整库存一致、且独立库存校验通过时，才考虑该支持范围的训练准入。信使补货等不可确定部分应继续保留歧义或补采。
