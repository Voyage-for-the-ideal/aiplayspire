后续实现更新：新增独立 `RunReconstructor(..., mode="policy")`，只导出确定的选择前前缀，禁止终局补推。默认价值模式及下文首次审计记录保留。地图越界已修复，本机 38 局逐层地图处理均通过；严格胜局前缀保留 11 条选牌＋2 条 Boss 遗物，不能视为全量覆盖率。当前实现边界、服务器命令及新报告结构见 [非战斗策略文档](NONCOMBAT_POLICY.md#服务器-run-首版-bc2026-10-25)。

## 修正结论

仓库已经有 `selectcard/src/reconstructor.py::RunReconstructor`，不是只有原始日志解析。它从初始牌组与遗物出发，应用购买、删牌、营火、事件、遗物替换及蛋类升级等变化，向后续选牌传递状态。`data_pipeline.py::process_run` 进一步校验终局牌组／遗物，并添加地图、历史及部分钥匙信息。

因此，**商店完整库存不可恢复，不代表商店之后的选牌牌组也无法恢复**。已购买物品和删牌日志已经被现有重放器用来维护后续状态。上一版仅强调“状态有缺口”，没有充分列出现有实现的覆盖，应以下表为准。

## 状态能力与两个限制

重放器已经维护：牌组 ID／升级次数、遗物 ID、楼层、进阶、HP、max HP、金币；角色由对局上下文补入。数据流水线另添加地图与历史。它没有通用的遗物计数、药水槽、卡牌 misc／瓶装绑定、完整菜单和明确的不确定性证据输出。

**限制一：现有输出是选择后状态。** `replay()` 在 `self.deck.append(picked)` 后生成选牌快照，在 `_add_relic(boss_relic)` 后生成 Boss 快照，并明确标记 `state_timing: post_action`。这是现有价值网络的训练接口。直接用该状态训练“应该选哪张牌”，会把选中牌已经入组等结果带入输入。新策略需要在应用动作之前导出，不能只修改时间标签或普遍通过删除一张牌逆推。

**限制二：终局对账参与了历史补推。** 构造函数默认调用 `_reconcile_all_diffs()`，以终局 `master_deck` 的差分推断未记录的删牌、变化和随机升级；涅奥的一些遗物效果还读取终局 `relics`。部分分配使用启发式，例如对差分列表取首项／末项。终局对账一致不能证明每个中间状态唯一正确。

原策略计划要求“终局牌组仅用于审计，不用于补造历史”。复用时应保留日志明确支持的状态传播，分离补推来源，并对无法证明的字段标记未知或排除相应样本；终局记录仍可以用于独立校验。没有隐式修正的对局也不能自动视为全部状态已通过审计，因为仍存在同层时序、资源时点等问题。

## 本机实跑证据

仅对本机 38 份 `.run` 在内存执行重放与现有转换；没有运行全量重建、真实模型训练或部署。

| 项目 | 结果 |
|---|---:|
| 重放正常返回 | 38 局 |
| 普通选牌快照 | 401 条 |
| Boss 遗物快照 | 26 条 |
| 快照时间类型 | 全部 427 条为 `post_action` |
| 终局牌组一致 | 35／38 局 |
| 终局遗物一致 | 38／38 局 |
| 使用隐式牌组修正 | 13 局，38 次添加、41 次移除 |

这些数量不是严格选择前样本的可恢复率。原始日志有 402 条选牌记录和 29 组 Boss 遗物记录；现有快照导出还包含同候选池去重、Boss 跳过不导出等行为，因此条数不同，相关规则应在策略导出时复核。

另有现存数据流水线问题：直接运行 `process_run` 时，14 局在添加地图上下文的 `forward_consistent_positions` 中触发 `IndexError`（地图行索引越界）。其余 14 局被现有转换接纳，产出 89 条旧格式快照；10 局被过滤，分别为无样本 3、终止楼层非法 2、trial 2、牌组对账失败 3。该异常记录在本机审计中，本次没有改动重放器或地图生产逻辑，不能把它当作原始日志信息不可恢复的证据。

审计产物：`debug/policy-reconstruction/replayer-audit-20261025.json`。其中还保留一个合成例子：只更改终局牌组，当前构造器输出的第 1 层牌组随之变化，验证了终局对账确实参与构建，而非仅做结束时校验。

现有数据流水线回归 29 项通过；这些合成回归通过不覆盖上面发现的本机地图越界问题。命令（从 `selectcard/src` 执行）：

```powershell
conda run --no-capture-output -n spire python -m unittest test_data_pipeline
```

完整训练归档本机仍缺失，本报告不提供全量覆盖率。

## 对路线的影响

无需从零重写所有状态重建，也无需因商店库存缺失而放弃后续选牌记录。优先复用“普通选牌＋Boss 遗物”的现有重放骨架，增加选择前状态和来源／不确定性审计；营火、地图、简单事件按确定子集扩展。自动实机采集优先补齐商店完整库存、多阶段事件、药水与目标选择等缺口。是否扩展为全量严格恢复，仍由后续审计决定。
